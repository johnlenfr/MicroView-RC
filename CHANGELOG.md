# Changelog

All notable changes to **MicroView RC** are documented in this file.

The project keeps the transmitter firmware version as the main public release
number. Receiver and ATtiny85 firmware versions are listed when relevant.

## [4.1.17] - 2026-09-23

### Changed
- Improved the `RF DEBUG` latency/retry layout from `L1.5MSR0` to `L1.5MS/R0`.
- Kept retry count `R` based on the nRF24L01+ `OBSERVE_TX.ARC_CNT` register.
- No change to RF timings, alert logic, endpoints, receiver behavior, or the
  ATtiny85 one-wire protocol.

### Components
- Transmitter: **4.1.17**
- ATtiny85 supervisor: **3.17.1**
- Receiver: **3.19a**

## [4.1.16] - 2026-09-23

### Changed
- Removed the dependency on `radio.getARC()` for compatibility with older RF24
  libraries.
- Read the nRF24L01+ `OBSERVE_TX` register directly and used `ARC_CNT` bits
  `3..0` as the retry counter `R`.
- Kept `L` measured only around `radio.write()`.
- Preserved uppercase `MS` and `S` units to avoid unsupported OLED glyphs.

### Components
- Transmitter: **4.1.16**
- ATtiny85 supervisor: **3.17.1**
- Receiver: **3.19a**

## [4.1.15] - 2026-09-23

### Added
- Added retry information `R` to the `RF DEBUG` page.
- Added explicit time units to debug values.
- Added the first complete user-manual/documentation package.

### Notes
- This version initially relied on `radio.getARC()`, which is not available in
  some older RF24 libraries.

## [4.1.14] - 2026-09-22

### Changed
- Increased MicroView-to-ATtiny85 polling to about **5 Hz**.
- Increased the timeout before TX battery data is considered stale.
- Improved TX battery display stability while keeping the master/slave
  one-wire protocol unchanged.

## [4.1.13] - 2026-09-22

### Changed
- Re-enabled normal nRF24 operation after the dedicated serial diagnostics.
- Kept the new MicroView/ATtiny85 **master/slave one-wire protocol**.
- Added asymmetric command decoding windows to better tolerate ATtiny85
  polling delay.
- Kept the on-screen `WIRE DBG` page for validation.

### Components
- ATtiny85 supervisor: **3.17.1**
- Receiver: **3.19a**

## [4.1.12] - 2026-09-22

### Added
- Introduced the master/slave one-wire protocol between MicroView D2 and
  ATtiny85 PB4.
- Added ordered ATtiny85 response frames containing command measurement, ACK,
  PB0/PB1 state, and TX battery.
- Removed asynchronous battery transmissions that could collide with alert
  commands.
- Increased command spacing to make decoding more robust.

### Diagnostics
- nRF24 intentionally disabled.
- Serial diagnostics enabled on MicroView D0/D1.

## [4.1.11] - 2026-09-22

### Fixed
- Fixed a transmitter compilation error caused by `txBatteryMv` being used
  before its declaration.
- Continued the dedicated serial one-wire diagnostic build.

## [4.1.10] - 2026-09-22

### Added
- Added temporary serial diagnostics at **115200 baud**.
- Allowed manual one-wire alert commands `0..9` from the serial monitor.
- Added traces for command pulses, ACKs, pin states, battery data, and unknown
  pulses.
- Temporarily used polling on the ATtiny85 to isolate PCINT-related issues.

## [4.1.9] - 2026-09-22

### Added
- Added one-wire timing and clock/fuse diagnostics.
- Added explicit comparison between pulse width generated by the MicroView and
  pulse width measured by the ATtiny85.

## [4.1.8] - 2026-09-22

### Added
- Added `WIRE DBG` diagnostics for MicroView/ATtiny85 communication.
- Added one-decimal-place formatting for debug measurements.

## [4.1.7] - 2026-09-22

### Changed
- Increased spacing between one-wire command pulse widths.
- Separated command, ACK, output-state, and battery pulse ranges.

## [4.1.6] - 2026-09-22

### Added
- Added temporary ATtiny85 PB0/PB1 output-state diagnostics.

## [4.1.5] - 2026-09-22

### Changed
- Reworked ATtiny85 alert output handling.
- Added explicit alert command decoding.
- Improved PB0/PB1 output control for buzzer and vibration outputs.

## [4.1.4] - 2026-09-22

### Added
- Expanded alert diagnostics and ATtiny85 communication checks.

## [4.1.3] - 2026-09-22

### Added
- Added per-model negative/positive endpoints.
- Added per-model throttle mode:
  - `BIDIR`
  - `FWD ONLY`
- Added global buzzer/vibration alert settings.
- Added alert levels `L1`, `L2`, and `L3`.
- Added RF and alert debug screens.

### Receiver
- Endpoint-capable receiver firmware line introduced.
- Receiver firmware later stabilized as **3.19a**.

---

## Versioning policy

- Public transmitter releases use numeric versions: `4.1.x`.
- Stable releases should be tagged in Git as `v4.1.x`.
- Receiver and ATtiny85 firmware keep their own independent version numbers.
- Experimental/debug builds should remain in Git history or branches rather
  than creating separate permanent source folders for every release.
